Examples and derivations live in the linked lessons. Use this page when a term blocks reading.

| Term | Meaning |
| --- | --- |
| Token / Token | One discrete text unit: a character, byte or learned piece; an ID is its integer label. |
| Vocabulary / Vokabular | All token IDs the model can predict; V is their count. |
| Scalar, vector, matrix, tensor / Skalar, Vektor, Matrix, Tensor | One number; a list of numbers; a table; a number array with any number of axes. |
| Shape, B/T/D/H/V / Shape, B/T/D/H/V | Axis lengths: batch examples, token positions, hidden width, attention heads and vocabulary. |
| Parameter / Parameter | A stored trainable number, such as a weight. Training changes it. |
| Activation / Aktivierung | An intermediate value calculated for a particular input; different from a stored weight. |
| Embedding / Embedding | A lookup table turning a token or position ID into a learned vector. |
| Logit, softmax / Logit, Softmax | An unrestricted score; the operation turning a row of scores into positive probabilities summing to one. |
| Loss, NLL, cross-entropy / Loss, NLL, Kreuzentropie | Prediction penalty. For one true next token, negative log likelihood is -ln(probability assigned to it). |
| Perplexity / Perplexität | exp(mean NLL). A uniform choice among four tokens has NLL ln(4) and perplexity 4; compare only with the same tokenizer/data. |
| Gradient, backpropagation / Gradient, Backpropagation | Sensitivities of loss to parameters; the chain-rule algorithm computing them backwards through the graph. |
| Optimizer, learning rate / Optimizer, Lernrate | The rule for updating parameters using gradients; the step-size control in that rule. |
| Batch, microbatch, accumulation / Batch, Microbatch, Accumulation | Examples processed together; a smaller chunk; collecting several chunks’ gradients before one update. |
| Epoch, step / Epoche, Schritt | One pass through a dataset; one optimizer update. Several microbatches may form one step. |
| Causal mask / Kausale Maske | An allowed-position map preventing a prediction from using future input tokens. |
| Padding, loss mask / Padding, Lossmaske | Filler tokens making sequences equally long; a selection of which targets count toward the loss. |
| Residual, normalization, FFN / Residual, Normalisierung, FFN | Add a block’s input back to its output; rescale feature values; a feed-forward network applied separately at each position. |
| Pretraining / Pretraining | Learning next-token prediction from text. It does not itself teach reliable instruction following. |
| Train / validation / test | Data used for updates / choosing configurations / final evaluation after choices are frozen. |
| Overfitting / Überanpassung | Training gets better while unseen-data quality stagnates or worsens; tiny-batch overfit is intentionally used as a mechanics check. |
| Baseline, ablation / Baseline, Ablation | The unchanged reference experiment; a controlled comparison changing one component. |
| Seed, checkpoint, resume / Seed, Checkpoint, Resume | A random-generator starting point; saved experiment state; continuation using that state. |
| Leakage, memorization / Leakage, Memorierung | Held-out information enters training/selection; reproducing seen content instead of generalizing. |
| Paired seeds, uncertainty / Gepaarte Seeds, Unsicherheit | Run baseline and change with matching seeds; variation showing how fragile the observed difference may be. |
| FLOP, throughput, memory / FLOP, Durchsatz, Speicher | One floating-point operation; tokens processed per second; bytes needed for parameters, gradients, optimizer and activations. |
| Mixed precision / Gemischte Präzision | Some operations use smaller numeric formats to reduce cost, with a float32 fallback in this course. |
| Temperature / Temperatur | Divisor applied to logits before softmax; below 1 sharpens the distribution, above 1 flattens it, and 0 means greedy. Order never changes ([I01](/llm-engineering-course-pages/inference-decoding)). |
| Greedy decoding / Greedy Decoding | Always take the most probable next token; deterministic for a fixed prompt, what `do_sample=False` and `temperature=0` mean ([I01](/llm-engineering-course-pages/inference-decoding)). |
| Top-k / top-p (nucleus) sampling / Top-k-/Top-p-Sampling | Sample only among the k most probable tokens / the smallest set whose cumulative probability reaches p, renormalised ([I01](/llm-engineering-course-pages/inference-decoding)). |
| EOS token / EOS-Token | End-of-sequence marker; a decoder stops when it is produced, otherwise at `max_new_tokens` or the context limit ([I01](/llm-engineering-course-pages/inference-decoding)). |
| KV cache / KV-Cache | Keys and values of every previous position, stored per block so each new token is projected once and attends over the cache ([I01](/llm-engineering-course-pages/inference-decoding)). |
| Streaming / Streaming | Sending each generated token as soon as its step finishes instead of waiting for the whole answer ([I01](/llm-engineering-course-pages/inference-decoding)). |
| AdamW / AdamW | Optimizer keeping a smoothed gradient `m` and squared gradient `v` per parameter, with decoupled weight decay applied separately from the adaptive step ([E01](/llm-engineering-course-pages/pretraining)). |
| Warmup / Warmup | The first steps of a schedule use a smaller learning rate; cosine decay then lowers it smoothly to a minimum ([E01](/llm-engineering-course-pages/pretraining)). |
| Gradient clipping / Gradient Clipping | If the whole gradient vector's norm exceeds a threshold, rescale it to that norm once per update, before the optimizer step ([E01](/llm-engineering-course-pages/pretraining)). |
| Held-out data / Held-out-Daten | Data excluded from parameter updates; validation data is held out for choosing settings, a test set only for the final measurement ([E03](/llm-engineering-course-pages/evaluation)). |
| Contamination / Kontamination | Evaluation content that also appears in training or selection data, so a score no longer measures generalization ([E02](/llm-engineering-course-pages/data-quality), [C03](/llm-engineering-course-pages/company-evaluation)). |
| Data card / Data Card | A short record of a dataset: source, generator, license, splits, counts, hashes and exclusions ([E02](/llm-engineering-course-pages/data-quality)). |
| Model card / Model Card | A short record of a trained model: base, data, configuration, measured results, limitations and what it is not approved for ([T01](/llm-engineering-course-pages/bigram-baseline), [C03](/llm-engineering-course-pages/company-evaluation)). |
| Quantization / Quantisierung | Storing weights in fewer bits (for example 4-bit NF4) to cut memory; QLoRA trains higher-precision adapters over a frozen quantized base ([A02](/llm-engineering-course-pages/adaptation-comparison)). |
| RAG, SFT, LoRA / RAG, SFT, LoRA | Retrieval of external text at request time ([R01](/llm-engineering-course-pages/rag-build)); supervised fine-tuning on prompt/response pairs with the loss on response tokens only; adaptation through small trainable low-rank matrices beside a frozen base ([A01](/llm-engineering-course-pages/sft-lora)). |
| DPO / DPO | Direct preference optimization: train the policy so the chosen response's log-probability rises relative to the rejected one, measured against a frozen reference and scaled by beta ([A03](/llm-engineering-course-pages/dpo)). |
| Reward model / Reward-Modell | A model trained on chosen/rejected pairs to score responses; it is a proxy for the true task quality and can be exploited ([A04](/llm-engineering-course-pages/rlhf-bridge)). |
| KL divergence / KL-Divergenz | How far one probability distribution has moved from another; used as a penalty to keep a trained policy close to its reference ([A04](/llm-engineering-course-pages/rlhf-bridge)). |
| PPO / PPO | Proximal policy optimization: a policy-gradient update whose probability ratio is clipped so one step cannot move the policy too far ([A03](/llm-engineering-course-pages/dpo), [A04](/llm-engineering-course-pages/rlhf-bridge)). |
| RLHF / RLHF | Reinforcement learning from human feedback: fit a reward model on preferences, then optimize the policy against it under a KL penalty ([A04](/llm-engineering-course-pages/rlhf-bridge)). |
